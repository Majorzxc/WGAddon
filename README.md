# WGRegionList

Аддон для **WorldGuard**, который позволяет хранить регионы в отдельных файлах и папках —
удобно, когда регионов сотни и тысячи. Каждая папка привязывается к миру, а регионы из её
файлов работают в WorldGuard так же, как его собственные: флаги, приоритеты, наследование,
`/rg info`, `/rg flag` и т.д.

Регионы самого WorldGuard продолжают работать как раньше, его настройки и `regions.yml`
не меняются.

## Требования

| | Версия |
|---|---|
| Сервер | Paper 1.21.4 и новее |
| WorldGuard | 7.0.13 и новее |
| WorldEdit | любая версия для вашего сервера (или FastAsyncWorldEdit) |
| Java | 21+ |

## Установка

1. Положите `WGRegionList-<версия>.jar` в `plugins/` (WorldGuard и WorldEdit должны быть установлены).
2. Запустите сервер — появится `plugins/WGRegionList/` с `config.yml` и примером
   `regions/world/example.yml` (полностью закомментирован).
3. Настройте привязку папок к мирам в `config.yml` и выполните `/wgrl reload`.

## Структура

```
plugins/WGRegionList/
├── config.yml
└── regions/
    ├── world/              ← папка, привязанная к миру world
    │   ├── spawn.yml
    │   ├── shops.yml
    │   └── cities/         ← вложенные папки тоже читаются
    │       ├── north.yml
    │       └── south.yml
    └── nether/
        └── arenas.yml
```

- Файлы — `*.yml` и `*.yaml` с любыми именами, в любых подпапках.
- Файлы и папки, имя которых начинается с точки, пропускаются — так можно временно
  «выключить» файл (`.old.yml`) или переименовать его в `*.yml.disabled`.

## config.yml

```yaml
worlds:
  world: world            # мир: папка
  world_nether: nether
  world_the_end:          # несколько папок для одного мира
    - end_spawn
    - end_arenas

sync:
  enabled: true           # сохранять изменения, сделанные в игре, в файлы аддона
  interval-seconds: 5     # как часто проверять изменения (в отдельном потоке)
  delete-removed: true    # /rg remove удаляет регион и из файла

restore-native-parents: true
debug: false
```

Одна папка может принадлежать только одному миру.

## Формат файлов

Такой же, как у `plugins/WorldGuard/worlds/<мир>/regions.yml`, — регионы можно просто
вырезать оттуда и вставить в файлы аддона.

```yaml
regions:
  spawn:
    type: cuboid
    min: {x: -50, y: -64, z: -50}
    max: {x: 50, y: 320, z: 50}
    priority: 10
    flags:
      pvp: deny
      greeting: 'Добро пожаловать!'
    owners:
      groups: [admin]
    members: {}

  market:
    type: poly2d
    min-y: 60
    max-y: 90
    points:
    - {x: 10, z: 10}
    - {x: 30, z: 10}
    - {x: 20, z: 30}
    flags: {build: deny}
    parent: spawn          # родитель может лежать в другом файле или в самом WorldGuard

  __global__:
    type: global
    flags: {creeper-explosion: deny}
```

Чтение терпимее, чем у WorldGuard: `priority` можно не указывать (будет 0), `type`
определяется по ключам, если его нет, регистр ключей не важен. Флаги разбирает сам
WorldGuard, поэтому поддерживаются все флаги, включая флаги других плагинов.

## Как это работает

- Регионы из файлов добавляются в WorldGuard как **transient**-регионы: WorldGuard использует
  их во всех проверках, но никогда не сохраняет в своё хранилище (ни в `regions.yml`, ни в
  MySQL/SQLite). Поэтому данные WorldGuard и аддона не смешиваются.
- Если ID региона из файла совпадает с регионом самого WorldGuard, используется регион
  WorldGuard, а в консоли выводится предупреждение. Если ID повторяется в двух файлах аддона,
  загружается тот, чей путь идёт раньше по алфавиту.
- Наследование работает в обе стороны: регион аддона может быть дочерним для региона
  WorldGuard и наоборот. WorldGuard при запуске не видит родителей из аддона и отбрасывает
  такую связь — аддон восстанавливает её (опция `restore-native-parents`, только для
  YAML-хранилища WorldGuard).
- После `/wg reload`, `/rg load` и загрузки новых миров регионы аддона подключаются заново
  автоматически.

## Изменения из игры

При `sync.enabled: true` изменения регионов аддона, сделанные в игре, записываются обратно в
их файлы:

| Команда | Что меняется в файле |
|---|---|
| `/rg flag` | только изменённый флаг |
| `/rg addmember`, `/rg addowner`, `/rg removemember`, … | `members` / `owners` |
| `/rg setpriority` | `priority` |
| `/rg setparent` | `parent` |
| `/rg redefine` | геометрия (`type`, `min`/`max` или `points`) |
| `/rg remove` | регион удаляется из файла (если `delete-removed: true`) |

Меняются только затронутые ключи — комментарии, порядок, оформление и ваши собственные
ключи в файле сохраняются. Запись атомарная (через временный файл).

Новые регионы, созданные через `/rg define`, остаются в WorldGuard — перенесите их в файл
аддона вручную, если нужно.

## Команды

Право — `wgregionlist.admin` (по умолчанию у операторов). Алиас — `/wgrl`.

| Команда | Описание |
|---|---|
| `/wgrl reload` | перечитать `config.yml` и все файлы регионов |
| `/wgrl info` | миры, папки, количество файлов и регионов, ошибки |
| `/wgrl find <id>` | в каком файле лежит регион |
| `/wgrl save` | сразу сохранить изменения из игры, не дожидаясь проверки |

## Отказоустойчивость

- Ошибка в файле никогда не снимает защиту: если файл не читается (ошибка синтаксиса YAML),
  ранее загруженные из него регионы остаются как были; битый регион пропускается, а его
  прошлая версия сохраняется. Подробности — в консоли.
- Файлы аддона меняются только точечно и атомарно; файлы WorldGuard аддон не меняет никогда.
- Удаление регионов из файлов выполняется только после проверки, что WorldGuard не
  перезагружал регионы в этот момент.

## Производительность

- Вся работа с файлами и регионами — в отдельном потоке `WGRegionList-Worker`; основной
  поток сервера не нагружается.
- Регионы добавляются в WorldGuard одной операцией (одна перестройка пространственного индекса
  вместо перестройки на каждый регион).
- При `/wgrl reload` регионы с неизменённой геометрией обновляются на месте, без перестройки
  индекса.
- Проверка изменений — один поиск в хеш-таблице на регион; файлы пишутся только при реальных
  изменениях.

## Ограничения

- Восстановление связей «регион WorldGuard → родитель из аддона» работает только с
  YAML-хранилищем WorldGuard. С MySQL держите такие регионы вместе (оба в аддоне или оба в
  WorldGuard).
- Если другой плагин меняет флаги через прямой доступ к карте флагов (`getFlags().put(...)`),
  а не через API WorldGuard, такое изменение не попадёт в файл.
- При `sync.enabled: false` изменения из игры живут до перезагрузки — источником правды
  остаются файлы.

## Сборка

```bash
./gradlew build
```

Готовый jar — `build/libs/WGRegionList-<версия>.jar`. Каждый push собирается в GitHub
Actions: юнит-тесты, сценарный тест на настоящих классах WorldGuard и запуск настоящего
сервера Paper (1.21.4 и последней версии) с WorldEdit и WorldGuard.
